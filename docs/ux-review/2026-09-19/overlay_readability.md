## 오버레이 적대 검토: 게임 화면 가림 · 가독성 · 정보 밀도 · 글만 읽어도 어떤 덱인지 아는가

제일 급한 문제는 별칭 자체가 틀린 덱이 있다는 점입니다. 다이아+ 목록 맨 윗줄 S 덱 별칭이 '검은 가시 베이가'인데, 보드에 베이가가 없습니다(실제로는 워윅 리롤 덱). 그 밖에 글자 크기, 두 등급 체계가 똑같이 보이는 문제, 덱 요약 화면에 덱 이름이 없는 문제, 가로 화면에서 목록이 세로로 거의 전부를 가리는 문제가 확인됐습니다.

**읽기 전에**
- **스크린샷은 옛 데이터로 찍혔습니다.** 그때 데이터에는 별칭·설명 필드가 없어서, 앱이 자기 대체 규칙(`Models.kt:275-302`)으로 별칭을 만들었습니다. 그래서 스크린샷에는 '달빛 카직스', 'G' 줄처럼 지금 데이터에 없는 글이 나옵니다.
- 그래서 레이아웃·크기·색은 스크린샷으로, 별칭·설명·등급 글은 지금 `decks.json`(77덱)과 수집기 코드로 판단했습니다.
- 가린 넓이는 패널 테두리 픽셀을 검출해 쟀고, 1dp = 2.625px로 계산했습니다.
- 에뮬레이터 배경은 게임이 아니라 홈 화면이므로, 밝은 게임 위 가독성은 코드의 색과 불투명도로 판단했습니다.
- 파일을 고치거나 에뮬레이터·adb를 쓰지 않았습니다. 분석용 스크립트만 스크래치패드에 만들었습니다.

### R1. 별칭이 보드·캐리와 어긋남 (보고된 7개 + 추가 3개)
- **심각도:** 치명
- **게임 중 장면:** 다이아+ 구간 목록 맨 윗줄이 'S 검은 가시 베이가 · 5레벨 리롤 / 5레벨 리롤 · 워윅·말파이트 캐리'입니다. 베이가를 들고 이 덱을 고르면 보드에 베이가가 없습니다. 프로필 카드상 사용자 티어가 다이아 IV라 가장 자주 볼 구간입니다. 골드~에메랄드에서는 S 2번째 '사냥꾼 시비르'의 메인 캐리가 애쉬이고, A 첫 줄 '나무정령 렝가'는 카직스 리롤 덱입니다.
- **근거:**
  - `m-f51648c22b`의 보드는 말파이트·워윅·덩굴정령·어스름늑대·돌거북·렉사이·다이애나·아지르이고 베이가가 없습니다. '약탈자 워윅'과 같은 보드입니다.
  - 별칭 속 챔피언이 상위 2캐리에 하나도 없는 덱이 7개입니다.

    | 별칭 | 실제 캐리 |
    |---|---|
    | 나무정령 렝가 | 카직스·헤카림 |
    | 개화 세트 시비르 | 아리·애쉬 |
    | 날렵이 티모 | 베이가·르블랑 |
    | 선봉대 아펠리오스 | 아무무·덩굴정령 |
    | 원시 시비르 | 니달리·말파이트 |
    | 주문술사 아리 | 카시오페아·피들스틱 |
    | 검은 가시 베이가 · 5레벨 리롤 | 워윅·말파이트 (베이가는 보드에도 없음) |

  - 추가로 3개가 더 있습니다.
    - '사냥꾼 시비르': 메인 캐리 애쉬가 별칭에 없습니다.
    - '나무정령 이즈리얼 드레이븐': 앞에 나온 이즈리얼이 3순위 캐리입니다.
    - '주문술사 카직스': 덱 특성이 싸움꾼·전쟁기계·지옥불·경쟁자뿐이라 주문술사가 아예 없습니다.
  - 원인은 두 규칙이 따로 도는 데 있습니다. metatft 덱 별칭은 metatft 조합 이름 조각(구별용 유닛)을 옮기고(`fetch_decks.py:1317-1327`), 설명은 캐리 순위를 씁니다(`1379-1388`).
  - 새 규칙이 오히려 나빠졌습니다. 같은 11유닛 덱이 앱 대체 규칙으로는 '달빛 카직스'(`l4_land_list`, `s0_aph_land`)였는데, 지금 수집기 별칭은 '나무정령 렝가'입니다.
- **고칠 방법:**
  - metatft 덱 별칭을 '{대표 시너지(주 특성)} {1순위 캐리}'로 바꿉니다. 조합 이름 조각의 유닛은 상위 2캐리일 때만 씁니다.
  - `verify.py`에 세 가지 검사를 넣고, 어기면 수집을 실패시킵니다.
    - 별칭의 챔피언이 모두 보드에 있는가
    - 첫 챔피언이 1·2순위 캐리인가
    - 별칭의 특성이 덱 특성에 있는가
  - 앱 쪽 보험: 목록 줄에서 별칭 챔피언이 캐리 목록에 없으면 대체 규칙 별칭을 씁니다.
- **규모:** S (수집기 규칙 + 검증). 앱 보험까지 하면 M.
- **확신도:** 높음

### R2. 두 등급 체계가 같은 글자·같은 색으로 보임
- **심각도:** 높음
- **게임 중 장면:** 골드~에메랄드에서 S만 켜면 13줄 중 8줄이 중국 한정 덱입니다(구간 안에서 절반을 S로 매긴 덱 7개 + 편집 덱 1개). 사용자는 'S = metatft 평균 4.25등 미만'으로 믿고 고릅니다.
- **근거:**
  - 중국 한정 덱은 대상 덱의 앞 절반이 S, 나머지가 A입니다(`fetch_decks.py:1293-1296`). 그래서 B·C·D가 없고, B·C·D 칸을 꺼도 중국 덱은 줄지 않습니다.
  - 평균 등수 척도도 다릅니다. 중국 S는 lol.qq 평균 2.07~2.96, metatft S는 4.01~4.22입니다. 그런데 둘 다 같은 분홍 'S'로 표시됩니다.
  - 둘을 구분하는 표시는 별칭 줄 오른쪽 끝의 5dp(13px) 호박색 점뿐입니다(`OverlayContent.kt:689-692`, `802-810`).
    - 등급 글자에서 약 278dp 떨어져 있습니다(`l4_land_list`).
    - 오버레이 안에 뜻을 알려 주는 범례가 없습니다.
    - 점 색이 B 등급 노랑과 ΔE2000 5.1로 비슷합니다(적록색약 기준 2.0).
  - 같은 9유닛 보드가 '처형자 자이라'(중국 S)와 '처형자 말파이트'(metatft A)로 나란히 뜹니다(목록 9번·16번).
  - 편집 덱 '검은 가시 니달리'(`14317`)는 통계가 비어 있어 모든 구간에 나옵니다. 등급은 편집 등급 'S'인데 색은 A의 주황입니다(`OverlayContent.kt:396-400`, `UiUtils.kt:69-75`). 정렬은 등급 없음 취급이라 B 줄들 아래 맨 끝에 붙습니다(`DeckSearch.kt:311`, `317-321`). 게다가 편집 내용이 지난 패치 기준입니다.
  - 옛 데이터에서는 설명 없는 파란 'G'까지 세 번째 체계였습니다(`s2_portrait`, `OverlayContent.kt:402-404`).
- **고칠 방법:**
  - 중국 한정 등급은 채움 없는 테두리 글자로 바꾸고, 등급 칸(22dp → 28dp)에 9sp '中'을 붙입니다. 오른쪽 끝 점은 없앱니다.
  - 구간 칩을 길게 누르면 범례를 한 줄 보여 줍니다: '中 = 중국 한정 덱끼리 매긴 상대 등급'.
  - 편집 덱은 등급 색을 다른 등급 색으로 빌리지 말고 '편' 표시를 쓰고, 등급대로 정렬합니다. 지난 패치 기준 편집 덱은 오버레이에서 뺍니다.
- **규모:** M
- **확신도:** 높음

### R3. 덱을 알아보는 핵심 글이 10sp
- **심각도:** 높음
- **게임 중 장면:** 폰을 가로로 30~40cm에서 들고 2~3초 흘끗 봅니다. 12sp 굵은 별칭은 읽히지만, '빠른 8레벨 · 아펠리오스·니달리 캐리'는 한글 한 자 높이가 약 1.35mm입니다.
- **근거:**
  - 10sp인 곳: 설명 `OverlayContent.kt:698`, 캡션 `875`, 구간 칩 `1165`, 빈 목록 안내 `604`, 시너지 칩 `855`. 앱 자체 글자 토큰의 최소는 12sp / 10.5sp입니다(`Theme.kt:113`, `116`).
  - 10sp 한글은 30cm에서 15.5분각, 40cm에서 11.6분각입니다. ISO 9241-303 / ANSI-HFES 100 계열 권고는 최소 16분각, 권장 20~22분각입니다.
  - 폭 여유가 충분합니다. 설명 최대 폭이 10sp에서 200dp, 12sp에서 240dp인데 줄 폭은 가로 262dp, 세로+카드 235dp입니다.
  - 그래서 2줄 허용(`SUMMARY_MAX_LINES`, `732`)은 지금 한 번도 쓰이지 않습니다.
  - 대비는 문제가 아닙니다. 설명 9.35:1, 흰 화면이 5% 비쳐도 8.33:1입니다.
- **고칠 방법:**
  - 설명은 12sp, 줄 간격 15sp로 올립니다. 가로에서는 전부 1줄에 들어가고, 세로+카드에서만 1개가 2줄이 됩니다.
  - 캡션·구간 칩·빈 목록 안내는 11sp로 올립니다.
- **규모:** S
- **확신도:** 수치는 높음, 권고 인용은 중간

### R4. 덱 요약 화면에 '무슨 덱인지' 글이 없음

- **근거:**

  - 별칭은 머리줄 버튼 7개(각 28dp, `1178-1222`)를 놓고 남는 폭에만 들어갑니다.
    - 전적을 연결한 가로 좁은 창: 남는 칸 약 76dp(실측 약 78dp, `l3_land_expand`). 77개 중 42개가 잘리고, 잘린 글이 서로 같아지는 묶음이 7개입니다.
    - 겹치는 예: '기원자 모르…'(덩굴정령/타릭), '나무정령 아…'(이즈리얼/자야), '검은 가시 베…'(3개), '요정 트리스…', '전쟁기계 자…'.
    - 세로+카드: 남는 칸 53.7dp가 최소 폭 56dp(`393`, `1188`)보다 좁아 별칭을 아예 숨깁니다.

- **고칠 방법:**
  - 본문 첫 줄에 '별칭(12sp 굵게) · 운영(11.5sp)'을 한 줄로 넣습니다. 높이는 약 18dp만 늘어납니다.
  - 머리줄에는 등급만 둡니다.
  - 또는 '앱 열기'·'티어 카드' 버튼을 목록 머리줄로만 옮깁니다.
- **규모:** S
- **확신도:** 높음

### R5. 가로 목록은 화면 높이 거의 전부를 가리는 세로 띠 / 보고된 수치 일부 틀림
- **심각도:** 높음
- **게임 중 장면:** 계획 단계에서 내 벤치·아이템을 보며 덱을 골라야 합니다. 그런데 패널을 어느 가로 위치에 두든 그 폭의 화면을 위아래 끝까지 덮어서, 매번 접고 펼쳐야 합니다(2탭). 기본 위치가 좌상단(`OverlayService.kt:119`, `928`)이라 처음에는 왼쪽 1/3을 전부 덮습니다.
- **근거 (측정):**

  | 상태 | 스크린샷 | 가린 넓이 |
  |---|---|---|
  | 가로·좁게·카드 | `l4_land_list` | 27.9% + 카드 5.7% = 33.6% |
  | 가로·넓게·카드 | `l14_wide` | 35.4% + 5.7% = 41.1% |
  | 세로·좁게·카드 | `g2_list_grades` | 32.8% (카드 끄면 약 29.8%) |

  - 가로·좁게에서 패널 세로 범위는 화면 높이의 85%입니다. 에뮬레이터에서 시스템 바를 뺀 가용 영역으로는 98%입니다. 넓게 보기에서는 가로로도 화면 폭의 56%를 덮습니다.
  - 실제 게임처럼 시스템 바가 숨으면 패널이 머리줄 38 + 검색줄 39 + 목록 300 = 377dp가 되어 화면 높이의 92%입니다. 패널 최대 높이가 '가용 높이 − 8dp'(`281`, `753`)라 가로에서는 사실상 상한이 없습니다.
  - 구현자 보고 대조:
    - 세로 32% — 맞음 (카드 켠 상태 기준)
    - 카드 켜면 40% — 틀림. 세로에서는 카드가 +5.7%p 더하지만 패널이 300dp에서 273dp로 좁아져 순증가는 약 3%p입니다.
    - 가로 40% — 좁게는 34%라 틀림, 넓게는 41%라 맞음.
  - 보이는 덱 수: 줄 간격 실측 67dp(좁게)·69dp(넓게)라, 목록 300dp에 4.5줄 / 4.3줄이 보입니다.
    - '좁은 모드 4~5' — 맞음
    - '넓은 모드 약 6' — 틀림. 넓게 보기가 목록 줄에서 바꾸는 것은 얼굴 크기(22 → 24dp, `710`)뿐이라 오히려 줄이 줄어듭니다.
  - 골드~에메랄드 기본(S·A·B) 목록은 56개라 한 화면 4.5줄이면 약 12화면입니다.
- **고칠 방법:**
  - 가로 목록 줄을 '[등급][별칭 12sp][메인 캐리 얼굴 2개 20dp] / [설명 12sp]'로 줄입니다. 줄 높이가 약 45dp가 됩니다. 전체 얼굴 줄은 넓게 보기일 때만 보여 줘서 넓게 보기에 역할을 줍니다.
  - 가로 목록 상한을 200dp로 둡니다. 그러면 패널이 약 277dp(화면 높이 67%)가 되면서도 지금과 같은 4.4줄이 보이고, 위에 붙이면 화면 아래 1/3이 빕니다.
  - 보수적인 대안: 얼굴 줄 줄바꿈을 막고 '+N'으로 표시합니다.
- **규모:** M
- **확신도:** 측정은 높음, 게임 조작 영향은 중간

  - 접미사는 별칭 글자가 겹칠 때만 붙고, 보드가 겹치는 경우는 보지 않습니다(`fetch_decks.py:1391-1416`).

### 꼭 고칠 것 상위 3개
1. **R1 별칭 오류:** 사용자가 원한 '글만 읽어도 아는' 글 자체가 틀려서 덱 선택을 잘못 이끕니다. 수집기 규칙과 검증을 고치면 됩니다.
2. **R3 설명 10sp → 12sp:** 한 줄 바꾸면 되는데 가독성 이득이 가장 큽니다. 폭 여유가 있어 가로에서는 줄도 늘지 않습니다.
3. **R2 두 등급 체계 구분:** 'S'라는 글자에 대한 신뢰를 무너뜨립니다.

그다음 순위는 R4(덱 요약 화면에 이름·설명 넣기)와 R5(가로 목록 높이 상한 + 압축 줄)입니다. 사용자 요구의 '글만 읽어도'를 더 무겁게 보면 R4를 3위에 올릴 수 있습니다.

- 대비 설계가 탄탄합니다. 설명 9.35:1(흰 화면이 비쳐도 8.33:1), 등급색은 모두 5.7:1 이상이고, 코드 주석에 대비 계산이 남아 있습니다.
- 기본 상태가 40dp 접힌 칩(화면 0.7%)이고, 덱 요약은 가로에서 약 300×145dp(화면 12%)라 게임 중 띄워 둘 만합니다. 보던 덱·레벨·목록 자리를 서비스가 기억해서 접었다 펴는 비용이 낮습니다.
