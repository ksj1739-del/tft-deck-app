### S4. 프로세스가 죽으면 조용히 사라지고, 직접 띄운 창은 앱을 열어도 돌아오지 않는다 (중간)

  2. 앱을 열 때 KEY_USER_OVERLAY가 참이고 창이 안 떠 있으면 '복원' 표시를 붙여 다시 띄웁니다. 이 경로에서는 selectDeck(null)을 건너뜁니다.
  3. 설정에 배터리 최적화 제외 안내를 넣습니다.
  4. 닫은 기록을 prefs에 저장합니다.
- **규모:** M
- **확신도:** 중간. startForeground 거절 여부는 OS와 제조사마다 확인해야 합니다. 앱을 열어도 직접 띄운 창이 돌아오지 않는 공백은 코드로 확실합니다.

- **규모:** S
- **확신도:** 높음

### S11. 권한이 회수되거나 감지 상태를 모를 때, 창은 숨는데 알림은 '감지 중'이라고 한다 (낮음)
- **게임 중 장면:**
  1. 사용 기록 접근 권한을 끄면 TFT를 켜도 아무것도 뜨지 않는데, 알림은 "TFT가 켜지면 알아챕니다"라고 합니다.
  2. 오버레이 권한이 없으면 '다시 띄우기'를 눌러도 반응이 없습니다.
  3. 2시간 넘게 TFT를 연속으로 켜 둔 상태에서 서비스가 되살아나면 감지 상태가 Unknown으로 굳습니다. 그러면 창이 숨습니다.
- **근거:**
  - 권한이 없으면 상태를 바꾸지 않고 그대로 돌려줍니다(GameDetector.kt:90).
  - 첫 조회는 2시간만 보고, 그 안에 이벤트가 없으면 상태를 유지합니다(:72, 124, 161-165).
  - 자동 모드에서는 TFT가 앞에 있다고 알아야 창을 보입니다(OverlayService.kt:425, 435).
  - 오버레이 권한이 없으면 아무 말 없이 끝납니다(:255-258).
- **고칠 방법:**
  - 권한이 없다는 상태를 따로 두고, 알림에 '권한 켜기' 액션을 붙입니다.
  - 상태가 Unknown이면 숨기지 말고 보여 줍니다.
  - 첫 조회에서 이벤트가 없으면 queryUsageStats 결과로 보강합니다.
- **규모:** S
- **확신도:** 1과 2는 높음, 3은 중간

### S12. 판 결과 알림이 다음 판 초반에 소리를 낸다 (낮음)
- **근거:** 판 종료 판정이 최대 15분 늦습니다(GameSession.kt:67-68). 결과 알림 채널은 IMPORTANCE_DEFAULT라 소리가 납니다(:321).
- **고칠 방법:** TFT가 앞에 있으면 `setSilent`로 소리를 끄고 칩 배지만 보여 줍니다.
- **규모:** S
- **확신도:** 중간

### S13. 화면 끝에 붙인 칩을 끌면 시스템 '뒤로' 제스처로 먹힐 수 있다 (낮음)
- **근거:** 자리 보정이 칩을 화면 끝까지 허용합니다(overlay/OverlayWindow.kt:47-57). 제스처 제외 영역(setSystemGestureExclusionRects)을 설정하지 않습니다. c0_drag_corner에서 칩이 오른쪽 끝에 붙어 있습니다.
- **고칠 방법:** onLayout에서 칩 영역을 제스처 제외 영역으로 등록합니다(API 29+).
- **규모:** S
- **확신도:** 낮음. 실기기 제스처 내비게이션에서 확인해야 합니다.

### S14. API 30 미만에서는 가로 검색 때 후보가 키보드에 가리고, 몰입 모드에서 가장자리까지 끌 수 없다 (낮음)
- **근거:** API 30 미만이면 창을 올리지 않고 바로 반환합니다(OverlayService.kt:478-479). 대체 영역 계산은 화면 크기에서 상태 표시줄 높이를 뺍니다(:747-753). 그래서 TFT가 바를 숨겨도 그만큼 끌 수 없습니다.
- **고칠 방법:** 가로 화면에서 검색을 시작하면 창을 y=0으로 올립니다. 영역은 getRealSize를 기준으로 계산합니다.
- **규모:** S
- **확신도:** 중간

- **스크롤 자리 복원은 아직 증명되지 않았습니다.** v4v5_compare의 두 장 모두 목록 첫 덱에서 시작합니다(v4_list_scrolled 포함).
- **TFT 몰입 모드의 영역 계산:** overlayArea()가 실제 창 기준 영역과 같은지 확인해야 합니다.
- **TFT가 다른 앱 오버레이를 숨기는지:** HIDE_OVERLAY_WINDOWS를 쓰면 창은 붙어 있는데 안 보이고, 앱은 그 사실을 모릅니다.
- **S1과 S4의 전제:** TFT 액티비티 구성, 그리고 스티키 재시작 때 startForeground가 실제로 거절되는지.

### 꼭 고칠 것 상위 3개
1. **닫은 뒤 되찾기 (S1, S2, S5):**
   - 닫기 차단을 판 단위(판 종료 신호 또는 40분)로 줄입니다.
   - 감지 중 창이 없을 때 알림 본문 탭을 '다시 띄우기'로 바꿉니다.
   - 알림의 '감지 끄기'가 설정값을 끄지 않게 합니다.
   - 모두 S 규모입니다.
2. **재부팅, 업데이트, 프로세스 종료 뒤 자동 복구 (S3, S4):**
   - 부팅과 업데이트 리시버를 추가합니다.
   - 재시작할 때 창을 먼저 붙이고 포그라운드로 올립니다.
   - 앱을 열면 직접 띄웠던 창도 복원합니다.
3. **게임 중 데이터 교체 보류 (S6, S10과 함께):**
   - 덱을 보는 중에는 새 피드를 미룹니다.
   - 사라진 덱은 스냅숏으로 보여 줍니다.
   - 오버레이에 데이터 나이를 표시합니다.

### 이미 잘 된 점
- **보던 자리가 이어집니다.** 보던 덱, 덱별 레벨, 목록 자리를 서비스가 저장하고 덱 id 이전까지 따라갑니다. 재시작 뒤 같은 덱과 레벨로 이어지는 것이 r1, r2, v3_level_kept_crop에서 확인됩니다.
- **창 경계 보정이 빠짐없이 걸립니다.** 끌기, 펼침, 회전, 복원 모두에 적용되고 가로와 세로 자리를 따로 저장합니다. 모서리 칩을 펼치면 안쪽으로 밀렸다가 접으면 제자리로 돌아옵니다(c0→c1→c2, l11, l12).
- **실패를 크래시 대신 받아 냅니다.** addView와 startForeground 실패는 runCatching으로 처리합니다. 감지 조회는 늦어진 구간을 되읽어 Foreground 상태에 굳는 것을 막습니다. 숨긴 창은 NOT_TOUCHABLE이라 게임 조작을 막지 않고, 닫기는 두 번 눌러야 합니다.
